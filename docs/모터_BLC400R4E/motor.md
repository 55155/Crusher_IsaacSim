## 1. 모터 BG42-BL4279E

유성기어 + 엔코더 일체형 BLDC. 모터부 `BL4279` + 기어박스 `PG42` 1/212.

### 모터부 (BL4279, 24V 사양)

| 항목 | 값 |
|---|---|
| 극수 / 상 | 8극 / 3상 |
| 정격 전압 | DC 24V |
| 무부하 속도 | 5,800 RPM |
| 무부하 전류 | 0.6 A |
| 정격 토크 | 0.185 Nm |
| 정격 속도 | 4,000 ±10% RPM |
| 정격 전류 | 4.8 ±10% A |
| 출력 | 77.5 W |
| 절연저항 / 내전압 / 등급 | 100MΩ min 500VDC / 500VAC 1min / B종 |

### 기어박스 (PG42, 1/212)

| 항목 | 값 |
|---|---|
| 감속비 | 212 : 1 |
| 감속기어 등급 | 4단 |
| 효율 | 50% |
| **정격 토크** | **25 kg·cm = 2.45 Nm** |
| 순시허용 토크 | 75 kg·cm = 7.36 Nm |
| 길이 L | 47.6 mm |
| 백래쉬 | ≤ 3° (무부하시) |
| Radial / Thrust play | ≤0.008mm / ≤0.03mm |

### 출력축 환산

| 항목 | 값 | 계산 |
|---|---|---|
| 정격 출력속도 | **18.9 RPM** | 4000 / 212 |
| 무부하 출력속도 | 27.4 RPM | 5800 / 212 |
| 모터 토크 × 감속 × 효율 | 19.6 Nm | 0.185 × 212 × 0.5 |
| **실사용 상한** | **2.45 Nm** | 기어박스 정격 |

**토크 한계는 모터가 아니라 기어박스다.** 모터 정격토크를 감속·효율까지 반영하면 19.6Nm 이
나오지만 기어박스 정격이 2.45Nm(순시 7.36Nm)이므로, 이 값을 넘기면 기어가 먼저 깨진다.
크러셔 부하 산정은 2.45Nm 기준으로 할 것.

**백래쉬 3°는 출력축 기준으로 크다.** 위치제어를 쓸 경우 방향 전환 때마다 그만큼 죽는 구간이
생긴다 — 한 방향 접근으로 설계하는 편이 낫다.

### 엔코더

| 항목 | 값 |
|---|---|
| 형식 | A/B 증감형, **차동 출력** (EA±, EB±) |
| 분해능 | 1,000 CPR |
| 커넥터 | 15핀 D-SUB |
| 전원 | +5V |

**CPR 해석 주의**: 1,000 CPR 이 체배 후 카운트(=250 PPR)인지 채널당 펄스 1,000개인지
자료에 명시가 없다. 드라이버 `분해능`(Mode 0x0A)에 넣을 값이 달라지므로,
설정 후 `0xA7` 피드백과 실제 1회전 각도를 대조해 확정할 것.

## 2. 드라이버 BLC-400R4E

| 항목 | 값 |
|---|---|
| 종류 | 3상 BLDC 드라이버, 엔코더 지원 (서보 운용 가능) |
| 제어 | 위치제어 / 속도제어 (각각 Kp·Ki·Kd + 정격전류) |
| 출력 | 192W ~ 384W (공급 전압에 따라) |
| 정격 전류 | 16 A |
| 통신 | RS-485 |
| 보호 | 과열, 저전압, 과전압, 스톨 |

**공급전압(VDD) 표기가 문서 안에서 3가지로 다르다** — 실물 라벨로 확인할 것.
상세구성 `DC 11~35V` / 전기적 특성 `DC 8~35V` / 결선구성 `DC 8~50V`.
모터가 24V 사양이므로 어느 표기를 따르든 **24V 공급이 정답**이다.

여유는 충분하다: 모터 정격 4.8A vs 드라이버 정격 16A.

## 3. 결선

### 드라이버 단자 배치 (매뉴얼 p.3 연결구성도 기준)

매뉴얼 본문의 핀아웃 목록(Hall 3pin / Encoder 4pin)은 **불완전하다.**
실제 기판에는 J1~J9 단자대가 있고, 홀 전원(J5)과 엔코더 전원(J7)이 **각각 따로** 있다.

| 단자 | 핀 |
|---|---|
| J3 | 1: U, 2: V, 3: W |
| J4 | 1: H1, 2: H2, 3: H3 |
| J5 | 1: GND, 2: 5V — **홀센서 전원** |
| J6 | 1: A, 2: B |
| J7 | 1: GND, 2: 5V — **엔코더 전원** |
| J8 | 1: GND, 2: VDD (DC 8~50V 입력) |
| J9 | 1: D+, 2: D−, 3: GND (RS-485) |

### 모터 본체 → 드라이버

| 신호 | 선 색 | AWG | 드라이버 |
|---|---|---|---|
| U_phase | 옐로우 | 20 | J3-1 (U) |
| V_phase | 그린 | 20 | J3-2 (V) |
| W_phase | 블루 | 20 | J3-3 (W) |
| Hall_u | 노랑 | 26 | J4-1 (H1) |
| Hall_v | 그린 | 26 | J4-2 (H2) |
| Hall_w | 블루 | 26 | J4-3 (H3) |
| Hall_Gnd | 검정 | 26 | **J5-1 (GND)** |
| Hall_5V | 빨강 | 26 | **J5-2 (5V)** |

> **색이 겹친다.** 상선(옐로우·그린·블루)과 홀선(노랑·그린·블루)이 같은 색 조합이다.
> 구분은 **굵기뿐** — 20AWG 굵은 쪽이 상선, 26AWG 얇은 쪽이 홀센서.
> 상선을 홀 커넥터에 꽂으면 홀센서가 즉시 파손된다. 굵기를 먼저 확인할 것.

### 엔코더 (15핀 D-SUB) → 드라이버

| D-SUB 핀 | 선 색 | 신호 | 드라이버 |
|---|---|---|---|
| 1 | 블랙 | EA+ | **J6-1 (A)** |
| 11 | 옐로우 | EB+ | **J6-2 (B)** |
| 3 | 화이트 | GND | **J7-1 (GND)** |
| 2 | 레드 | VCC | **J7-2 (5V)** |
| 13 | 블루 | EA− | 미결선 |
| 12 | 그린 | EB− | 미결선 |

**모터 엔코더는 차동인데 드라이버 입력은 단상(A/B/GND/5V)이다.** 그래서 EA−/EB− 는
받을 자리가 없다. 위 표대로 + 쪽만 연결하는 것이 기본이고, 노이즈가 문제되면 차동→단상
변환을 따로 넣어야 한다. (자료에도 "점퍼케이블을 통해 연결해가도 되십니다"라고만 적혀 있다.)

### 전원 · RS-485

| 드라이버 | 연결 |
|---|---|
| J8-2 (VDD) | DC 24V + |
| J8-1 (GND) | DC 24V − |
| J9-1 (D+) | 컨버터 A |
| J9-2 (D−) | 컨버터 B |
| J9-3 (GND) | 컨버터 GND |

로드셀(BS-105)과 달리 **GND 단자가 있으므로 3선으로 연결**한다.
컨버터는 LC529 를 쓸 경우 **스위치를 485 로** 둘 것 — 422 로 두면 아무것도 안 들어온다
(로드셀에서 이미 겪은 문제).

## 4. 드라이버에 넣어야 할 설정값

모터 스펙에서 바로 나오는 값들. 모터를 바꾸면 같이 고쳐야 한다.

| Mode | 항목 | 넣을 값 | 바이트 | 초기값 |
|---|---|---|---|---|
| 0x09 | 모터 정격속도 | 4000 RPM | `0x0FA0` | 0x0BB8 (3000) |
| 0x0B | 감속비 | 212.0 : 1 | `0x0848` (2120) | 0x000A (1.0) |
| 0x0A | 분해능 | **미확정** (CPR 해석 필요) | — | 0x0004 |
| 0x04/0x05 | 정격전류 | 4.8A → 48 | `0x30` | 정격전류 |

정격전류는 **모터 기준 4.8A** 로 잡는다(드라이버 16A 는 드라이버 자신의 한계).
기어박스 정격 2.45Nm 를 넘기지 않으려면 전류 상한을 더 낮게 두는 편이 안전하다.

## 5. RS-485 프로토콜 (MC-RS485 V1.0.1)

### 통신 설정
- 기본값 **9600bps, No parity, 8 data bits, 1 stop bit** (8N1)
- 초기 ID `0x00`, Broadcast ID `0xFF`
- 통신 응답시간 초기값 `0x01` = 100us

### 프레임 구조

```
[0xFF][0xFE][ID][Data크기][Checksum][Mode][payload ...]
  Header(2)   1      1         1       1      0~N
```

- `Data크기` = Checksum 부터 끝까지의 바이트 수 (Checksum + Mode + payload)
- `Checksum` = `~(ID + Data크기 + Mode + payload 전부) & 0xFF`
  - Header 와 Checksum 자신은 합산 제외
  - 검증: `FF FE 00 03 F5 06 01` → ~(00+03+06+01) = ~0x0A = 0xF5 ✓
  - 검증: `FF FE 00 07 76 01 00 46 50 03 E8` → 합 0x189, 하위 0x89, ~0x89 = 0x76 ✓

### 단위

| 항목 | 단위 |
|---|---|
| 위치 | 0.01 Degree (`0x4650` = 18000 = 180.00°) |
| 속도 | 0.1 RPM (`0x03E8` = 1000 = 100.0RPM) |
| 도달 시간 | 0.1 s |
| 전류 | 100 mA |
| 감속비 | 0.1 ratio |
| 통신 응답시간 | 100 us |
| 방향 | `0x00` = CCW, `0x01` = CW |

### 송신 명령

| Mode | 기능 | Data크기 | payload |
|---|---|---|---|
| 0x01 | 위치·속도제어 | 0x07 | 위치방향(1), 위치(2), 속도(2) |
| 0x02 | 가감속 위치제어 | 0x06 | 위치방향(1), 위치(2), 위치 도달시간(1) |
| 0x03 | 가감속 속도제어 | 0x06 | 속도방향(1), 속도(2), 속도 도달시간(1) |
| 0x04 | 위치제어기 설정 | 0x06 | Kp(1), Ki(1), Kd(1), 위치제어 정격전류(1) |
| 0x05 | 속도제어기 설정 | 0x06 | Kp(1), Ki(1), Kd(1), 속도제어 정격전류(1) |
| 0x06 | ID 설정 | 0x03 | ID(1) — 0x00~0xFE |
| 0x07 | 통신속도 설정 | 0x03 | 코드(1) — 0x00~0x11, 초기값 0x06(9600) |
| 0x08 | 통신 응답시간 설정 | 0x03 | 시간(1) [100us] |
| 0x09 | 모터 정격속도 설정 | 0x04 | RPM(2), 초기값 0x0BB8 |
| 0x0A | 분해능 설정 | 0x04 | 엔코더 pulse 또는 pole(2), 초기값 0x0004 |
| 0x0B | 감속비 설정 | 0x04 | 비율(2) [0.1ratio], 초기값 0x000A |
| 0x0C | 제어 On/Off | 0x03 | 0x00=On, 0x01=Off (초기값 On) |
| 0x0D | 위치제어 모드 | 0x03 | 0x00=절대, 0x01=상대 (초기값 절대) |
| 0x0E | 제어 방향 설정 | 0x03 | 0x00=CCW, 0x01=CW |
| 0x0F | 위치 초기화 | 0x02 | — |
| 0x10 | 공장 초기화 | 0x02 | — |

예제(문서 그대로)
- 위치·속도제어, ID0, CCW 180.00°, 100.0RPM: `FF FE 00 07 76 01 00 46 50 03 E8`
- 가감속 위치제어, ID0, CW 360.00°, 1.0s: `FF FE 00 06 C0 02 01 8C A0 0A`
- 가감속 속도제어, ID0, CCW 100RPM, 2.0s: `FF FE 00 06 F7 03 00 03 E8 14`
- 위치 초기화, ID0: `FF FE 00 02 EF 0F`

### 피드백 요청 (Data크기 0x02, payload 없음)

| 요청 | 내용 | 응답 |
|---|---|---|
| 0xA0 | Ping | 0xD0 |
| 0xA1 | 위치 | 0xD1 |
| 0xA2 | 속도 | 0xD2 |
| 0xA3 | 위치제어기 | 0xD3 |
| 0xA4 | 속도제어기 | 0xD4 |
| 0xA5 | 통신 응답시간 | 0xD5 |
| 0xA6 | 모터 정격속도 | 0xD6 |
| 0xA7 | 분해능 | 0xD7 |
| 0xA8 | 감속비 | 0xD8 |
| 0xA9 | 제어 On/Off | 0xD9 |
| 0xAA | 위치제어 모드 | 0xDA |
| 0xAB | 제어 방향 | 0xDB |
| 0xCD | 펌웨어 버전 | 0xFD |

**모니터링에 쓸 두 응답** (둘 다 Data크기 0x08, 전류가 함께 온다 — 부하 추정 가능)

| 응답 | payload |
|---|---|
| 0xD1 위치 피드백 | 위치방향(1), 위치(2)[0.01°], 속도(2)[0.1RPM], 전류(1)[100mA] |
| 0xD2 속도 피드백 | 속도방향(1), 속도(2)[0.1RPM], 위치(2)[0.1°], 전류(1)[100mA] |

주의: 0xD1 의 위치는 0.01° 단위인데 **0xD2 의 위치는 0.1° 단위**로 문서에 적혀 있다. 실물 확인 필요.

예제
- 위치 요청, ID0: `FF FE 00 02 5C A1`
- 위치 응답: `FF FE 00 08 90 D1 00 46 50 00 00 00` → CCW, 180.00°, 0.0RPM, 0.0A

### 제어 불능 시
문서 부록의 조치 — 제어 방향 설정 변경: `FF FE 00 03 EC 0F 01`

주의: 이 바이트열은 Mode 가 `0x0F`(위치 초기화)인데 설명은 "제어 방향 설정 변경"이다.
제어 방향은 Mode `0x0E` 이고, `0x0E` 로 계산해도 체크섬은 ~(00+03+0E+01)=0xED 가 되어
표기된 `0xEC` 와 맞지 않는다. **문서 오기로 보이므로 그대로 쓰지 말 것.**

### 확인된 것

| 통신 | COM5 / **9600 8N1 / ID 0**. Ping·설정 읽기/쓰기 모두 정상, 체크섬 일치 |

### 미해결 0 — 속도 지령값도 무시된다 (가장 중요)

**이 드라이버가 실제로 반응하는 것은 제어 On/Off 와 회전 방향뿐이다.**

속도만 바꿔 6회 시험한 결과:

| 지령 | 보고 속도 |
|---|---|
| 5.0 RPM | 109.9 RPM |
| 10.0 RPM | 109.3 RPM |
| 30.0 RPM | 109.3 RPM |
| 100.0 RPM | 109.2 RPM |
| 300.0 RPM | 109.4 RPM |
| 600.0 RPM | 109.3 RPM |

120배 범위로 지령해도 속도가 변하지 않는다. **감속 정지(속도 0.1RPM)도 듣지 않아
제어 Off 로만 멈춘다** — 정지 지령 후에도 109RPM 으로 20초 이상 계속 돌았다.

그러니 "속도제어는 정상"이라던 앞의 기록은 **"돌기는 한다"는 뜻일 뿐**이었다.
속도값을 바꿔 가며 확인하지 않은 것이 원인이다.

### 미해결 1 — 위치제어가 목표에서 멈추지 못한다 (폭주)

**⚠ 판매처 답이 오기 전까지 위치제어를 쓰지 말 것. 속도제어만 사용한다.**

거동이 `0x0F`(위치 초기화)를 보냈는지에 따라 갈린다.

| 순서 | 결과 |
|---|---|
| 제어 On → **0x0F** → 위치 지령 | 전혀 반응 없음 (위치·속도·전류 전부 0) |
| 제어 On → 위치 지령 (0x0F 생략) | **목표를 지나쳐 무한 회전 (폭주)** — 5회 시험 5회 재현 |

폭주 속도는 감속비에 비례한다. 212.0:1 에서 108RPM, **1.0:1 에서 3,400RPM**(모터 정격
4000RPM 근처)까지 올라갔다. 제어 Off(`0x0C`+`0x01`)로만 멈춘다.

무부하였으니 3,400RPM 으로 끝났지, 포크가 핸들에 물린 상태였으면 기어박스가 나갔다.

**원인 추정**: 위치 피드백이 655.36°에서 랩어라운드한 뒤 0.00 에 고정되는 구간이 있고
(속도 필드는 계속 정상), 드라이버가 "도달"을 영영 판정하지 못해 계속 미는 것으로 보인다.
감속비 212:1 이면 출력축 90°가 모터축 19,080°인데 위치 필드는 2바이트(최대 655.33°)라
애초에 표현이 안 된다.

소거한 변인 — 전부 동일 증상:
- 각도 1° / 3° / 5° / 90° / 360° / 655.33°
- 모드 0x01·0x02, 절대·상대, 도달시간 0.1~25.5s
- 감속비 212.0 / 1.0, 분해능 4 / 250 / 500
- 위치제어 정격전류 1.5A / 1.8A / 25.4A, 게인 50/10/10 ~ 254/254/254
- 제어방향 CW·CCW, 지령방향 CW·CCW, 공장 초기화(0x10) 직후
- 파워서플라이 2.5A → 150W(6.25A) 교체 후에도 동일

같은 시점 같은 배선에서 **속도제어는 즉시 정상 동작**한다(대조군).
상세 TX/RX 로그는 `vendor_log.txt`.

공장 초기화 후 정격속도가 매뉴얼 기본값 3000 이 아니라 **1300 RPM** 으로 돌아갔고
분해능 500 은 그대로 남았다. 판매처가 별도 기본값으로 세팅해 출고한 물건으로 보인다.

**대안**: 위치가 필요하면 속도제어 + 엔코더 피드백으로 **PC 쪽에서 위치 루프를 직접
닫는다.** 목표 각도에 도달하면 속도 0 을 보내 정지시키는 방식이면 드라이버의 위치 기능
없이도 된다. 단 위치 피드백의 랩어라운드를 소프트웨어에서 누적 처리해야 한다.

### 미해결 2 — 기동 시 드라이버 리셋

전류가 실리는 순간 통신이 약 4초 끊기고, 복구되면 위치가 0 으로 초기화되어 있다(= 리부팅).
**현재 파워서플라이 2.5A, 모터 정격 4.8A** 이므로 기동 전류를 못 받쳐 저전압 리셋이 나는
것으로 본다. **24V 6A 이상**(기동 여유 포함 8~10A) 으로 교체 필요.

단, 엔코더를 뺀 상태에서는 같은 2.5A 로 30초 연속 회전이 문제없었다. 즉 공급 부족이
상시 원인은 아니고, 폐루프 진입 후 진동·스톨로 전류가 급증할 때만 무너진다.

### 방향 조합

제어 방향(`0x0E`)과 지령 방향의 조합에 따라 거동이 다르다. 실측:

| 제어 방향 | 지령 방향 | 결과 |
|---|---|---|
| CW | CCW | 진동만 하고 회전 없음, 드라이버 리셋 |
| CCW | CCW | 무동작 |
| **CCW** | **CW** | **정상 회전** ← 이 조합을 쓸 것 |

### 피드백 해석 주의

- **위치 필드는 655.35°에서 랩어라운드**한다(2바이트 × 0.01°). 절대 위치로 쓰려면
  소프트웨어에서 누적 보정할 것.
- 장시간 회전 시 위치가 0 에 고정되는 구간이 관측됐다. 원인 미확인.
- 지령 30.0RPM 에 피드백 55.3RPM 으로 **지령과 피드백의 기준축이 다르다.** 미확정.
- 폴링은 **고정 sleep 이 아니라 프레임이 다 찰 때까지** 읽어야 한다. 12바이트 응답(0xD1)은
  9600bps 에서 12.5ms 이상 걸려, 고정 70ms 대기로는 놓치는 경우가 있었다.

### 현재 설정값 (복구 완료)

| 항목 | 값 |
|---|---|
| 모터 정격속도 | 4000 RPM |
| 감속비 | 212.0 : 1 |
| 분해능 | 500 |
| 제어 방향 | CCW |
| 위치제어 모드 | 절대 |
| 위치·속도 제어기 | Kp200 Ki100 Kd100, 전류 25.4A |

**전류 25.4A 는 공장값이다. 실사용 전 반드시 낮출 것** — 기어박스 순시 7.36Nm 기준
상한이 약 1.8A(0x12), 연속 2.45Nm 기준은 약 0.6A.

## 8. 해결 (2026-10-01) — 판매처 지정 설정으로 정상 동작

### 결론부터

**판매처가 지정한 설정으로 바꾸자 진동이 사라지고 위치제어가 정확해졌다.**

| 항목 | 값 | 비고 |
|---|---|---|
| 위치제어기 | **Kp 10 / Ki 1 / Kd 0 / 1800mA** | 출고값 Kp200 이 이 조합에는 과했다 |
| 속도제어기 | **Kp 10 / Ki 1 / Kd 0 / 1800mA** | 동일 |
| 분해능 | **1000** | 상세페이지 예제의 CPR÷4(=250) 규칙과 다름 |
| 위치제어 모드 | **절대** | 상대 모드는 정지하지 않는다고 판매처가 명시 |
| 제어 방향 | **CW** | 판매처 1차 회신으로 CCW → CW 변경 |
| 감속비 | 2120 (212.0:1) | |
| 모터 정격속도 | 1300 RPM | 공장 초기화 값 그대로. 실사용에 충분 |

판매처 회신 원문 — "1. 절대위치제어(상대위치제어시 정지안됨) / 2. kp 10 ki1 kd 0
정격전류1800(위치제어기·속도제어기 동일) — 모터성능이 높을수록 kp가 높아지면
불안정해집니다 / 3. 분해능은 1000으로 설정"

### 실측 성능

90도 왕복 10회 (좌표 300 ↔ 390):

| 항목 | 값 |
|---|---|
| 오차 | **±0.08도 이내** (평균 −0.014도) |
| 이동량 | 89.87 ~ 89.99도 |
| 소요 시간 | 1.11 ~ 1.12초 |
| 누적 오차 | 없음 (10회 뒤 제자리) |

180도·45도 단발 이동도 오차가 모두 **−0.07도로 일정**하다. 이동량과 무관한
고정 오프셋이므로 필요하면 지령에 0.07도를 더해 보정할 수 있다.

### ★ 위치 지령 시 좌표가 0으로 리셋된다

가장 중요한 발견이다. **위치제어 지령(`0x02`)을 보내는 순간 드라이버가 현재
위치를 0으로 리셋하고, 지령한 값만큼 이동한다.**

실측 — 499.88deg 에서 목표 519.88(= 현재+20) 을 보냈더니:

```
    t=0.026s      1.45deg     <- 지령 순간 0 으로 리셋됨
    t=0.074s      7.69deg
    t=0.936s    151.52deg
    정지 후     409.55deg     <- 20도가 아니라 500도 가까이 이동
```

따라서 **설정은 "절대"이지만 동작은 상대 위치제어다.**
지령값을 그대로 이동량으로 주면 된다 — 180도 돌리려면 `180`, 90도면 `90`.
현재 위치를 더하면 안 된다.

> 이 문서 7장에서 "경계를 넘는 목표를 주면 먼 길로 돈다"고 적은 것도 사실은
> 이 리셋 때문이었다. 현재 위치를 더해 목표를 만든 것이 원인이다.

### 운용 규칙

1. **전원 투입 = 위치 0.** 전원을 껐다 켜면 피드백이 0.00deg 에서 시작한다.
   설정은 EEPROM 에 유지된다.
2. **`0x0F`(위치 초기화)를 쓰지 말 것.** 보내면 이후 위치 지령이 전부 무시된다.
3. **지령값 = 이동량.** 절대 좌표를 계산해 더하지 않는다.
4. **좌표 상한 655.33도.** 지령 필드가 2바이트라 한 번에 줄 수 있는 최대값이다.
   모터 자체는 계속 돌 수 있고 좌표만 655.36 에서 0 으로 되감긴다.
5. **원점은 PC 쪽에서 관리.** 드라이버에 위치 오프셋을 저장하는 명령이 없다.
   누적 각도를 파일에 보관하고, 외력으로 틀어지면 기계적 스토퍼로 재원점.

### 속도제어 ↔ 위치제어 전환

크랭크 알고리즘(전진=속도제어, 후퇴=위치제어)이 성립하는 것을 확인했다.
속도제어로 회전 중에 위치제어 지령을 보내면 **별도 정지 과정 없이 전환**되고,
4회 반복 모두 −90.03 ~ −90.07도로 정확했다.

### 미확정

- **좌표 증감과 CW/CCW 의 대응.** 관측이 엇갈려 확정하지 못했다.
  실사용 전에 한 방향으로 크게 돌려 눈으로 확인할 것.
- **좌표 1도와 출력축 1도의 배율.** 180도 지령 시 출력축이 반 바퀴인지
  미확인. 배율이 1:1 이 아니면 지령값을 환산해야 한다.
