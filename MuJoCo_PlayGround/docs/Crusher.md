## 1. 전체 구조 개요

Crusher는 **크랭크-슬라이더(Crank-Slider)** 메커니즘으로 모터 회전운동을 직선 압축력으로 변환하는 정제 분쇄 장치입니다.

```
[Motor1 BLDC]
     │  (GEAR 1:212)
     ▼
[크랭크 L4_Shaft_1]  — hinge(z) — (crank r = 20 mm)
     │
[커넥팅 로드 L6_Link2_1]  — hinge(z) — (link 94 mm)
     │
[커넥팅 로드 L7_Link3_1]  — hinge(z)
     │  (weld equality: crank_slider_loop)
[슬라이더 L8_Link3_Shaft_1]  — slide(Y) — (충돌판 L9_PLATE)
     │
     ▼  ← 정제(Tablet) 충돌
```

- **구동 방향**: 크랭크 CCW(반시계) → 슬라이더 전진(−Y 방향)
- **스트로크**: 2 × r = 2 × 20 mm = **40 mm**
- **운전 속도**: 8 RPM (크랭크 기준)

## 2. 크랭크-슬라이더 메커니즘

### 2-1. 핵심 치수

| 파라미터 | 기호 | 값 | 출처 |
|---------|------|----|------|
| 크랭크 반경 | r | **20 mm** | L6_Link2_1 local pos x = 0.02 m |
| 커넥팅 로드 길이 (MJCF) | L_mjcf | **94 mm** | L7_Link3_1 local pos x = 0.094 m |
| 커넥팅 로드 길이 (유효) | L_eff | **80 mm** | 실제 핀 간 거리 (사용자 확인) |
| 슬라이더 스트로크 | S | **40 mm** | 2 × r |

> `L_mjcf = 94 mm`는 body origin 간 거리이며, 실제 크랭크 핀 ~ 슬라이더 핀 유효 길이는 **80 mm**입니다.

### 2-2. 기구학 (Kinematics)

크랭크 각도 θ 기준 슬라이더 위치 (근사, r/L << 1 가정):

```
x_slider(θ) ≈ r·cos θ + L·√(1 - (r/L)²·sin²θ)
```

슬라이더 힘 (준정적, 마찰 무시):

```
F_slider = τ_crank / (r × sin θ)
```

| θ | sin θ | F_slider (τ = 12.5 N·m, r = 0.02 m) | 비고 |
|---|-------|--------------------------------------|------|
| 90° | 1.000 | **625 N** | 실측 600–650 N ✓ |
| 60° | 0.866 | **722 N** | — |
| 45° | 0.707 | **884 N** | — |
| 30° | 0.500 | **1,250 N** | TDP(상사점) 근처, 이론 최대 |

### 2-3. 초기 자세

| 설정 | 값 | 설명 |
|------|----|------|
| 크랭크 초기각 | **−90° (−π/2 rad)** | `lock_crank` equality 고정 |
| 초기 안정화 | 500 step (Phase 1) | 구속 활성 상태에서 MuJoCo 수렴 |
| 모터 투입 | t = 2.0 s 이후 | `MOTOR_DELAY = 2.0 s` |

## 9. 정제(Tablet) 배치 좌표

정제는 **mocap body**로 삽입되어 충돌 벽으로 동작합니다.

| 항목 | 값 (world frame) |
|------|-----------------|
| X 위치 | **−47.879 mm** (충돌판 중심 정렬) |
| Y 위치 | `(WALL_Y_MM − half_thickness)` = 336.199 mm − t/2 |
| Z 위치 | **50.108 mm** (수직 높이) |
| 기본 밀도 | **1,200 kg/m³** |
| 자세 쿼터니언 | `[√2/2, 0, √2/2, 0]` → 장축 world-Y 방향 |

정제 두께 계산 (코드 기준):

```python
cd      = CV * 2 * R_mm          # crown depth [mm]
th      = R_mm * 0.20 + 2 * cd   # 총 두께 [mm]
half_th = th / 2.0
```

## 10. MuJoCo 솔버 설정

| 설정 | 원본 XML | 시뮬레이션 런타임 (`crusher_velocity_ctrl.py`) |
|------|---------|----------------------------------------------|
| solver | Newton | Newton (변경 없음) |
| iterations | 50 | 50 |
| timestep | 0.002 s | **0.001 s** (2배 세밀화) |
| integrator | Euler (기본) | **implicitfast** |

### `implicitfast` 선택 이유

velocity actuator의 explicit Euler 안정 조건: `kv × dt / J_eff < 2`

| 조건 | kv | dt | J_eff | 안정 지수 | 판정 |
|------|----|----|-------|----------|------|
| 원본 (크랭크 관성만) | 14.9 | 0.001 s | ~4.2e-5 kg·m² | ≈ 354 | 발산 ✗ |
| J_REFL body 주입 | 14.9 | 0.001 s | 0.324 kg·m² | ≈ 0.046 | 이론 안정 ✓ |
| → Newton 솔버 실패 | — | — | 23,000:1 비율 | — | 실제 발산 ✗ |
| **implicitfast** | 14.9 | 0.001 s | 무관 | 무제한 | **무조건 안정 ✓** |

`implicitfast`는 velocity/position actuator 힘을 암묵적으로 선형화하여 kv 크기와 무관하게 안정을 보장합니다.

## 11. 구동 사양 — 입력 모터·감속기·재질·샘플백 홀더

Crusher는 중앙에 모터의 회전운동을 선형운동으로 변환하는 **Crank-Slider Mechanism**을 이용한다. 링크의 길이는 다음과 같다.

| 링크 | 길이 |
|------|------|
| Crank | 2 cm |
| Connecting rod | 8 cm |
| Stroke | 4 cm |

### 11-1. 운전 RPM 선정

Crusher의 특성상 다양한 시도를 해보았으나, RPM이 매우 높을 시 진동에 의한 기구 결함이 발생하고, 너무 강할 경우 분쇄 후 압력에 의해 고형의 파우더들이 응집력을 가지게 되므로 회수에서 어려움이 발생한다. 따라서 RPM은 **20 RPM 미만의 매우 저 RPM 모터**를 사용하고 있다.

### 11-2. 입력 모터 — BL4281 (24 V, 77.5 W)

torque의 경우 입력 모터의 크기 및 전압·파워는 **BL4281, 24V 77.5W**이며, 스펙은 다음과 같다.

| 항목 | 값 | 단위 |
| --- | --- | --- |
| 극수 | 8 | - |
| 상 | 3 | - |
| 전압 | 24 | V |
| 상저항 | 0.55 | ohms |
| 무부하속도 | 5800 | RPM |
| 무부하전류 | 0.6 | A |
| 정격토크 | 0.185 | Nm |

## 12. 제어 알고리즘 — 타격·후퇴(strike–retract) 시퀀스

### 12-1. 현재 알고리즘 — 대칭 stall-반전 (기록용)

크랭크를 CCW 등속 구동하다가 정제에 막혀 **stall(속도≈0)** 이 검출되면 방향을
뒤집는 방식. 양방향을 동등하게 취급한다.

| 구현 | stall 판정 | 반전 |
|------|-----------|------|
| 실기(Real) | `rpm_buffer = deque(maxlen=5)`, `sum == 0` | `dir *= -1` |
| 시뮬([`crusher_velocity_ctrl_viewer.py`](../20260603/crusher_velocity_ctrl_viewer.py)) | `STALL_WINDOW_S=2.0s` 이동평균 `< STALL_EPSILON=4 RPM` | `motor_dir *= -1`, `REVERSAL_COOLDOWN=4.0s` |

구동 방향 규약(§1): **CCW → 슬라이더 전진(−Y, 정제 타격)**, CW → 후퇴.

### 12-2. 문제점

1. **주기(period) 비제어** — 반전이 stall 검출 시점에만 일어나 cadence가 불규칙.
   FEM/실험 동기화(스트로크당 일·N_f 카운트)에 불리.
2. **CW/CCW 토크 비대칭** — 대칭 stall-반전은 *양방향이 같은 힘으로 친다*고 가정.
   실제 모터는 CW·CCW 토크가 달라(아래 §12-8 진단) 한쪽으로는 충분한 타격력이,
   반대쪽으로는 부족한 힘이 나옴 → "반대로 돌려 반대편에서 친다"가 무의미.

### 12-3. 새 알고리즘 — 단일방향 타격 + 시간기반 후퇴 (FSM)

**강한 쪽(CCW)만 타격에 쓰고, 약한 쪽(CW)은 무부하 후퇴에만 쓴다.** 2-state
유한상태기계(FSM):

```
        ┌──────────────── 접촉 검출 ────────────────┐
        ▼                                           │
   [STRIKE: CCW]  ──접촉/stall──▶  [RETRACT: CW, 고정 ~3 s]  ──타이머 만료──┐
        ▲                                                                  │
        └──────────────────────────────────────────────────────────────────┘
```

- **STRIKE (CCW)**: 강방향 등속/토크로 정제 타격. 가볍게 접촉(짧은 윈도우 stall
  또는 전류 상승)하면 즉시 RETRACT로 전환.
- **RETRACT (CW)**: **고정 시간 `T_RETRACT ≈ 3 s`** 동안 후퇴. stall 판정 안 함.
- 만료되면 다시 STRIKE → 1 stroke 완료. 반복.

**핵심 — 왜 비대칭이 해소되나**: RETRACT는 정제를 이기는 동작이 아니라 **무부하로
슬라이더를 뒤로 빼는 것**뿐이라 약한 CW 토크로도 충분. 타격(부하 극복)은 항상
강한 CCW가 전담 → 토크 비대칭이 알고리즘에 영향을 주지 않는다. 주기도
`t_strike(접촉까지) + T_RETRACT` 로 예측 가능해진다.

### 12-4. 접촉 검출 & 파쇄(N_f) 검출

| 이벤트 | 신호 | 비고 |
|--------|------|------|
| **접촉 (STRIKE→RETRACT)** | 짧은 윈도우(예 5 샘플) 속도≈0, 또는 모터 전류 > `I_contact` | 비대칭 때문에 전류 임계는 **방향별**로 따로 |
| **파쇄 (N_f++)** | STRIKE 중 크랭크가 직전 접촉각 `+Δ_break` 를 **stall 없이 통과** | 정제가 눌려 깨져 슬라이더가 더 전진 → 트윈의 N_f·W* 측정 포인트 |
| **안전 (미접촉)** | STRIKE가 `T_STRIKE_MAX` 초과해도 무접촉 | 정제 소진/이탈 → 강제 RETRACT 또는 종료 |

> 직전 STRIKE의 접촉각을 저장해두고, 다음 STRIKE가 그 각을 의미있게 넘어서면
> "이번 타격에 균열 진전"으로 보고 `N_f` 를 센다. 이게 디지털 트윈(DataInventory.md
> A열)의 N_f 실측과 직접 연결된다.

### 12-5. 파라미터 (제안 초기값)

| 기호 | 의미 | 제안값 | 메모 |
|------|------|--------|------|
| `v_strike` | CCW 타격 속도 | 8 RPM (기존) | 강방향 |
| `v_retract` | CW 후퇴 속도 | 8–12 RPM | 무부하라 자유롭게 |
| `T_RETRACT` | 후퇴 시간 | **3.0 s** | 또는 후퇴각 `Δ_retract`로 환산 |
| `Δ_retract` | 후퇴각 | 15–30° (크랭크) | BDC 넘기지 않게 |
| `I_contact` (CCW) | 접촉 전류 임계 | 실측 캘리브 | 방향별 |
| `T_STRIKE_MAX` | 타격 타임아웃 | 5 s | 안전 |
| `Δ_break` | 파쇄 판정 진전각 | 5–10° | 노이즈 위로 |

### 12-6. 후퇴는 '힘'이 아니라 '해제'가 목적 — 준정적 근거

준정적(8 RPM) 운전이라 후퇴를 **멀리/오래 해도 타격력 이득이 없다.** 후퇴 거리는
다음 타격의 접근속도·충격을 바꾸지 못한다(velocity control이라 접근속도는 항상
`v_strike` 고정). 8 RPM 기준 운동에너지 추정:

```
크랭크 ω = 8·2π/60 ≈ 0.84 rad/s
슬라이더 v = r·ω = 0.02 × 0.84 ≈ 0.017 m/s (17 mm/s)
KE = ½·m·v² = ½·0.35·0.017² ≈ 5×10⁻⁵ J   (50 µJ)
파쇄 일 W ≈ 600 N × 0.1 mm ≈ 0.06 J
KE / W ≈ 0.08 %   → 충격(관성) 기여 무시 가능
```

타격력은 접촉각에서의 **정적 토크·기구 이득 `τ/(r·sinθ)`** 으로만 결정 → 후퇴
시간과 무관. 따라서:

- 후퇴의 목적은 타격이 아니라 **접촉 완전 해제 + 탄성 스프링백 복원**(다음 타격을
  0에서 재적재)뿐이다.
- 종료조건은 **시간(3 s/6 s)이 아니라 후퇴각 `Δ_retract` 도달**로. 시간은 안전
  타임아웃으로만 둔다.
- 특히 약한 CW 방향은 3 s 동안 실제 후퇴각이 작거나 들쭉날쭉할 수 있어 **각도
  기준이 사실상 필수**.
- 해제에 충분한 **최소량**만 빼면 되고, 그 이상은 cycle 시간 낭비(throughput↓).

### 12-7. 의사코드

```python
STATE, t_state = "STRIKE", now()
contact_angle  = None          # 직전 타격 접촉각
n_f = 0
while running:
    vel, ang, cur = read_crank()           # 속도, 각도, 전류(or 접촉력)
    if STATE == "STRIKE":
        cmd_velocity(+v_strike)            # CCW (강방향)
        # 파쇄: stall 없이 직전 접촉각 통과
        if contact_angle is not None and ang > contact_angle + D_BREAK and not stalled(vel):
            n_f += 1; log_fracture(now(), ang)
        if stalled_short(vel) or cur > I_CONTACT_CCW:   # 접촉
            contact_angle = ang
            STATE, t_state = "RETRACT", now()
        elif now() - t_state > T_STRIKE_MAX:            # 안전: 무접촉
            STATE, t_state = "RETRACT", now()
    else:  # RETRACT
        cmd_velocity(-v_retract)           # CW (약방향, 무부하)
        if now() - t_state >= T_RETRACT:   # 시간기반 — stall 무시
            STATE, t_state = "STRIKE", now()
```

> 시뮬에 이식할 위치: [`crusher_velocity_ctrl_viewer.py`](../20260603/crusher_velocity_ctrl_viewer.py)
> 의 stall 윈도우 블록(현 `stall_queue` 반전, L281–300)을 위 FSM으로 교체.

### 12-8. CW/CCW 토크 비대칭 — 원인 진단 (모터 결함 확정 전 점검)

비대칭을 "모터 결함"으로 단정하기 전에 절분 테스트를 권장. BLDC가 FOC로 제대로
구동되면 토크는 방향 대칭이라, 비대칭은 보통 다른 데서 온다.

| 가설 | 점검 방법 | 비고 |
|------|----------|------|
| 모터(전기) — 홀센서/정류 오프셋 | **무부하** 동일속도 CW vs CCW **전류** 비교 | 무부하에서 차이 나면 모터/드라이버 |
| 감속기 — 방향별 효율 | 무부하 백드라이브/구동 토크 측정 | 베벨+1/212–1/504, 효율 ~50% → **방향 의존 크다**. 결함 아닐 수 있음 |
| 기구/중력 — 크랭크 자중·마찰 | 정제 없이 자세별 토크 | 부하 시에만 차이면 기구·중력 |

> 무부하 전류가 대칭인데 부하 시 비대칭이면 **모터가 아니라 감속기/기구·중력**일
> 가능성이 큼. 어느 쪽이든 §12-3의 단일방향 타격 설계는 **원인과 무관하게** 안전
> (강방향만 부하를 받으므로).
